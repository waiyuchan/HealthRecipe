# 随机选菜、今天吃了啥和快收菜谱

## 首页的三个入口

1. **随机吃点什么**：可抽 1／3／6 道；继续遵守忌口、烹饪用时、近期做菜和吃饭记录去重；换组尽量不重复上一组。候选不足时不自动放宽限制。
2. **记下今天吃的**：一次填写多个菜名，用顿号、逗号或换行分开。做法不需要填写，菜谱盒子里没有也能保存。默认今天，可补录过去日期，支持餐别、份量、小记、修改与删除。
3. **想吃的菜，收进来**：填菜名，有做法就口述／输入，没有就留空。也可粘贴分享链接或分享文字。

只有准确匹配已有菜谱的菜才根据实际份量保存营养快照；单纯知道菜名不能判断食材和用量，因此不猜热量。未匹配记录会显示「热量尚未核算」。饮食回顾和近期去重会同时读取旧做菜记录与新的独立吃饭记录。

## 菜谱三条路线

- **知道做法**：按用户原话分步，保留原始口述；食材表可留空，后续补充。不自动增加材料、调味或烹饪动作。
- **只有菜名**：并行查找公开搜索结果与公开食谱索引；展示多个版本、来源与原文链接。选择后才读取完整正文，预览确认后保存。
- **已有分享链接**：识别下厨房、美食天下、豆果、小红书、The Woks of Life。短链接只允许在受支持站点内有限跳转，限制请求时间与页面大小；不携带用户浏览器 cookie、不登录、不破解验证。

支持 JSON-LD Recipe、三个中文站点的可见用料／步骤结构，以及小红书公开笔记中的明确「做法／步骤」段落或编号步骤。原文缺少方法时返回 partial，不根据菜名生成菜谱。部分来源不会列出独立食材表，做法可以先保存，但热量和购物用料需要以后补齐。

抓不到时可换来源、打开原文后粘贴可见正文，或存为「还想做的菜」。待找内容进入完整备份，继续补充后可发布；相同来源的移动／桌面版本按来源 ID 去重，已有菜谱不被静默覆盖。

## 来源实测与边界

2026-11-06 的本机网络实测：

- 下厨房返回滑动验证，美食天下出现 Cloudflare 验证，豆果返回访问限制或限流。它们的解析结构有固定样例测试，但不能据此宣称当前网络可完整抓取。
- 小红书提供分享链接／公开文字的解析路径；没有宣称能读取登录后内容、纯图片文字或视频口述。未部署 OCR 或视频转录。
- The Woks of Life 的公开 WordPress 搜索及 Recipe JSON-LD 可以访问。实测按「红烧肉」找到多个版本并提取；「番茄炒蛋」通过常见菜名搜索别名找到对应食谱，并在浏览器完成 10 项用料、6 个步骤的提取、预览和保存。**原文英文**会明确标注，不假装已经翻译成中文。
- 免费网页搜索入口可能限流、返回不相关内容或失效；结果会做受支持域名和菜名相关性过滤，失败时显示提示与各站的直接搜索入口。不会用无关搜索结果填充列表。

自动抓取不保证所有网站、链接和网络环境都成功。只处理用户选择的公开页面，保留作者和来源，供个人查阅；不做全站爬取、自动重发或公开转载。

## 语音

使用浏览器的 SpeechRecognition／webkitSpeechRecognition，用户点击后才申请麦克风与语音识别；浏览器可能调用自己的语音服务。可停止、编辑识别文字再保存。无该能力、权限被拒或识别失败时，保留已有文字，并提示键盘听写／手动输入。

自动化验证了语音事件接线和不可用回退，未对真实麦克风、设备授权、各种浏览器语音服务作统一成功保证。

## 数据与接口

SQLite `user_version=3` 在 v2 基础上增量增加：

- `meal_logs`：可没有 recipe_id 的真实吃饭记录；来源菜谱删除时保留菜名和历史营养快照。
- `meal_batches`：提交重试去重缓存，不作为用户资料导出。
- `recipe_drafts`：待找的菜名、已有原文与来源。

JSON v3 增加 `meal_logs` 与 `drafts`，兼容 v1／v2；完整恢复仍为单事务，失败回滚。

```text
GET/POST       /api/food-log
PUT/DELETE     /api/food-log/{id}
POST           /api/capture/search
POST           /api/capture/preview
POST           /api/capture/save
GET/POST       /api/capture/drafts
PUT/DELETE     /api/capture/drafts/{id}
```

食材未知的口述菜谱不会在有忌口条件时作为已核验候选放行；英文原料补充了常见厨房词和过敏原名称匹配，仍不替代复合配料、包装和交叉接触核查。
